# Game Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a room feel like a complete playable turtle-soup round with clear status, final-guess behavior, question-limit boundaries, and clean case notes.

**Architecture:** Keep game rules in `roomStore` so Socket.IO and future APIs share the same behavior. The React room UI reads the existing `RoomState` and disables/labels controls based on `status` and remaining questions.

**Tech Stack:** TypeScript, React, Socket.IO, Vitest.

## Global Constraints

- No new backend service or database in this phase.
- No complex scoring or account progression.
- Keep existing `RoomStatus` values.
- Final guesses do not consume ordinary question count.
- Pinned case notes should be idempotent per answer.
